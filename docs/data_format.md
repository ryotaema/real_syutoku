# データ形式

カメラの自動認識・命名規則・保存される形式です．各スクリプトの保存フォルダの構成は [usage.md](usage.md) の各項目にもあります．旧形式データの変換は [legacy_conversion.md](legacy_conversion.md) を参照してください．

## カメラ自動認識

すべてのスクリプトは起動時に接続されているカメラを自動検出し，**D435・D405・Gemini 336 のどれでも動作**します．

1台だけつながっていればそのカメラを自動で使います．2台以上つながっている場合は起動時に
カメラ選択ダイアログが表示されます（画面の無い環境ではターミナルで番号を選びます）．

```
使用カメラ: Intel RealSense D435  (シリアル: 12345678)
```

| | D435 | D405 | Gemini 336 |
|---|---|---|---|
| メーカー / SDK | Intel / pyrealsense2 | Intel / pyrealsense2 | Orbbec / pyorbbecsdk |
| カメラコード | `d435` | `d405` | `g336` |
| color | ✓ | ✓ | ✓ |
| depth | ✓（1単位 = 1mm） | ✓（1単位 = 0.1mm） | ✓（1単位 = 1mm） |
| ir_left / ir_right | ✓ | なし | ✓ |
| pointcloud | ✓ | ✓ | ✓ |
| 深度カラーマップ | alpha=0.4 固定（~637mm 飽和） | フレーム内相対正規化 | alpha=0.4 固定（~637mm 飽和） |
| 動画録画（`record/`） | ✓ | ✓ | ✓（.bag は Orbbec 独自形式） |

機種によって画質・深度の出方が異なるため，**どのカメラで撮ったかは必ずデータに残ります**．
ファイル名・セッションディレクトリ名の先頭がカメラコード（[データ命名規則](#データ命名規則)）になり，
`metadata.json` の `camera` に機種名・型番・シリアル番号・SDK・解像度・FPS・depth の単位が記録されます．

```json
"camera": {
  "name": "Orbbec Gemini 336", "model": "G336", "serial": "G336_SERIAL_NUMBER",
  "backend": "orbbec", "resolution": [640, 480], "fps": 30, "depth_scale": 0.001
}
```

点群（.ply）は機種によらず RealSense Viewer と同じ座標系（y・z 反転，単位 m）で保存されるので，
どのカメラで撮った点群も同じように扱えます．

D405 接続時は IR ストリームを無効化し，color と depth のみを収集します．深度カラーマップは D435 が絶対距離を色で表す固定 alpha 方式，D405 がフレーム内の最近〜最遠を 0〜255 に正規化する相対方式に自動切り替えされます（D405 は距離レンジが狭く固定 alpha では飽和しやすいため）．

## データ命名規則

すべての収集データは，ファイル名だけで「どのカメラの・いつの・何枚目の・何の画像か」が
分かるように統一されています．学習用に1つのフォルダへ集約しても，アノテーションツールに
まとめて読み込ませても，どのセッションのデータか判別できなくなることがありません．

```
{cam}_{YYMMDD}_{HHMMSS}_{NNNNN}_{mod}.{ext}

d435_260707_101741_00042_c.jpg
 │        │      │      │     └─ モダリティコード
 │        │      │      └─────── セッション内のショット連番（撮影時刻ではない）
 │        │      └────────────── セッション開始時刻
 │        └───────────────────── 取得日
 └────────────────────────────── カメラコード
```

| 要素 | 説明 |
|------|------|
| `cam` | `d435` / `d405` / `g336`（自動判別）．nyx660_syutoku 側は `nyx` を使うため，リポジトリを跨いでも衝突しません．未登録の機種は `unk` になります（起動時に警告） |
| `YYMMDD` | 取得日 |
| `HHMMSS` | セッション開始時刻．1プロセス＝1セッションで固定です |
| `NNNNN` | セッション内のショット連番．**同一ショットの color/depth/ir は同じ番号を共有します** |
| `mod` | モダリティコード（下表） |

**モダリティコード**

| コード | 内容 | コード | 内容 |
|--------|------|--------|------|
| `c` | color | `i1c` | IR 左カラーマップ |
| `d` | depth（16bit raw PNG） | `i2c` | IR 右カラーマップ |
| `dc` | depth colormap | `pc` | 点群（.ply） |
| `i1` | IR 左 | `pt` | クリック座標（.txt） |
| `i2` | IR 右 | `det` | YOLO 描画済み |

連番はショット単位で共有されるため，末尾のモダリティコードを差し替えるだけで対応する
ファイルを引けます（`..._00042_c.jpg` ↔ `..._00042_dc.jpg`）．YOLO のラベル `.txt` や
labelImg の `.xml` も stem が一致するので自動的に紐づきます．

撮影条件など，ファイル名に載せない情報は各セッションの `metadata.json` に記録されます．

### セッションディレクトリとタグ

```
<出力先>/<YYMMDD>/<prefix>[_<tag>]/<モダリティ>/<ファイル>
```

`--tag` を付けると，セッションディレクトリ名にだけ任意の名前が付きます
（ファイル名の桁は増えません）．

```bash
python3 collect/dataset_collect_photo.py --tag greenhouse
# → images/260707/d435_260707_101741_greenhouse/color/d435_260707_101741_00001_c.jpg
```

## 全データ取得（dataset_collect_photo --all-data）

保存先は `config.yaml` の `output.images_dir` 配下です．各ファイルは同じショット番号を共有します．
RGBは既存の処理用JPEGとロスレスPNGの両方を保存し，深度・IRの生データもPNGで残します．
メタデータの `frames[].files` に，そのショットの各ファイルの相対パスが入ります．

| データ | 保存先 | 内容 |
|---|---|---|
| RGB | `color/*_c.jpg` | 既存の収集画像と同じJPEG |
| RGB（ロスレス） | `color_raw/*_cr.png` | 取得画素を保持したPNG |
| 深度 | `depth/*_d.png` | 16bit PNG．距離は画素値 × `metadata.camera.depth_scale` [m] |
| 深度可視化 | `depth_colormap/*_dc.jpg` | プレビュー用の疑似カラー画像 |
| 位置合わせ前の深度 | `depth_raw/*_dr.png` | ネイティブの深度座標系・解像度を保持 |
| 左右IR | `ir_left/*_i1.png` / `ir_right/*_i2.png` | 対応機種のみ，8bit PNG |
| IR可視化 | `ir_left_color/*_i1c.jpg` / `ir_right_color/*_i2c.jpg` | 左右IRの疑似カラー画像 |
| 点群 | `pointcloud/*_pc.ply` | 無効深度を除いた点群．単位m，RealSense Viewer座標系（x右・y上・前方−z） |
| カメラ情報 | `intrinsics.json` / `camera_settings.json` | 内部パラメータ・撮影設定 |
| 取得記録 | `metadata.json` | 機種・シリアル番号・保存ファイル・フレーム番号・取得時刻・画像サイズ |

D435・Gemini 336では左右IRも保存します．D405はIR非対応のため，
`unavailable_modalities` にその旨を記録し，対応するRGB・深度・PLYを保存します．
`depth/` はカラー座標系に位置合わせ済み，`depth_raw/` は位置合わせ前です．
`calibration.json` にネイティブの内部・外部パラメータも保存します．
PLYはRGB付きで，距離による追加の切り捨ては行いません．
